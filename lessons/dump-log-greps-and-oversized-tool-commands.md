Three tooling traps from 2026-09-11, each of which silently produced a wrong or empty answer.

1. `grep -ao "Remix live: [^\r\n]*"` truncates every line at the first `r`, `n` or backslash: inside a POSIX bracket expression `\r` and `\n` are the literal characters backslash, r and n, not escapes. `Remix live: see` and `fp=1322365f038bcb67 fp` are the tell (cut before `seen`, before `fpraw`). Use `grep -aoP "Remix live: .*"` (Perl regex, `.` stops at newline). The same applies inside a `[regex]::Match` pattern only when the string is single-quoted; PowerShell double-quoted `"[^\r\n]"` expands the escapes and is fine.

2. `bin\log\RPCS3.log` is held with no sharing while the game runs: `[System.IO.File]::Open(..., FileShare::ReadWrite)` throws "being used by another process" on every poll, while Git Bash `grep -a` reads it. The run-start banner is mirrored to `bin\remix_dump.log` anyway (`grep -aoP "Remix run-start: .*pid=<pid>.*"`), and that file is never locked - read everything from there, from a `tail -c` of the last 20-40 MB, and note the banner has spaces in `build=Sep 11 2026 10:37:57`, so `[^ ]*pid=` never matches it.

3. A single Bash tool call whose heredocs total more than ~30 KB fails with `ENAMETOOLONG: name too long, uv_spawn` before running anything - the whole command is one argv string. Write each patch script to the scratchpad with the Write tool and run them with a short command. Anchored, count-asserted replacements (`s.count(old) == N` or abort) with a tab marker (`»`) in the anchors keep the patches exact against tab-indented C++ and preserve CRLF/LF per file (RemixTransforms.* and RemixGSRender.h are CRLF; RemixGSRender.cpp, the tests and the conf are LF).
